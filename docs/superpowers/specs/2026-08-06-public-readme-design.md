# 面向普通访客的项目 README 设计

## 目标

将仓库现有的 TI DriverLib 空工程模板说明，改写为面向 GitHub/Gitee 普通访客的项目介绍页。README 的首要目标是让读者快速知道项目是什么、获得了什么成果、能完成哪些演示，以及源码大致包含哪些部分。

## 受众与语气

- 主要面向不了解仓库内部实现的普通访客、赛事关注者和潜在使用者。
- 使用简体中文，语气简洁、清晰、偏成果展示。
- 技术细节只保留能够帮助读者理解项目的内容，不展开参数、通信帧和编译配置。

## 页面结构

1. 标题区：使用“2026全国大学生电子设计竞赛”和“钢球平衡控制小车”作为主标题层级。
2. 荣誉区：突出“全国大学生电子设计竞赛一等奖”。
3. 项目简介：概括基于 TI MSPM0G3507 的车载平衡滚球运动控制系统，以及循迹、滚球平衡和视觉监测目标。
4. 项目成果/功能：用短条目介绍循迹行驶、静止滚球控制、行驶中滚球保持、指定位置保持、视觉数据和 OLED 显示等功能。
5. 项目演示：以静止往返、从 A 点出发完成单圈、行驶中保持滚球位置等场景描述可展示效果；不填写仓库中没有证据支持的具体实测成绩。
6. 技术概览：简要列出 MSPM0G3507、C 语言、Keil、红外循迹、编码器、电机、IMU、摄像头视觉通信和舵机摆杆控制。
7. 代码结构：只列出 `Control/`、`Hardware/`、`tools/host_tests/`、`keil/` 等关键目录及其用途。
8. 开发说明：保留简短的 Keil 工程入口和构建命令，方便有兴趣的开发者继续了解；不写成完整调试手册。
9. 结尾：说明项目为竞赛作品源码，并保留必要的开源/使用提示。

## 内容约束

- 不再保留原 TI 空工程模板的 LaunchPad 外设表、迁移建议和低功耗建议。
- 不虚构视频、图片、在线演示链接、队伍信息、实测分数或未确认的硬件型号。
- 与仓库实际目录和源码功能保持一致；生成文件和 Keil 临时产物不作为主要项目内容介绍。
- README 只做文案与结构更新，不修改固件代码、工程配置或生成文件。

## 验收标准

- 首屏能够直接看到赛事、项目名称和一等奖信息。
- 普通访客无需阅读源码即可理解项目用途、主要功能和演示场景。
- 关键技术栈和目录信息准确，但整体篇幅和技术深度明显低于开发文档。
- README 中的文件路径、构建入口和功能描述均能在当前仓库找到对应依据。
- Markdown 标题、列表、代码块和链接格式正常，无明显占位符或矛盾表述。
